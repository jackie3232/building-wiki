## 1 · 驱动范围（Agent 驱动）

**条款**
应用分两层——**驱动层 = Agent**（含它调用的一切：函数内脚本、云托管的自动化引擎）；
**交互层 = 前端**（只做输入与展示）。

**数据流**
前端输入 → 前端以 **ACP** 调 Agent → Agent 全程执行（理解 / 装配 / 上传 / 调 MCP）→
结果经事件流回传 → 前端渲染。

**判据**
1. 前端零业务逻辑（只收发 + 渲染）。
2. 前端调的是 **Agent**（`/acp` 端点），不是自动化端。
3. 自动化端虽独立部署，但逻辑上属驱动层——只被 Agent 调用。

**附**
体素数据走云存储直连（预签名 URL）：**Agent 只回传引用，不搬数据**。

**依据**（实盘，2026-09-27 核实）
- `web/config.js` → `ACP_URL = .../v1/aibot/bots/agt-building-8gp5in9y2e59d69c/acp`
- `web/app.js` `runAgent()` → `fetch(ACP_URL, { jsonrpc:"2.0", method:"session/prompt", ... })`
- `web/app.js` → `fetch(state.boxes)` 直连拉取体素数据
- `server/cloudbaserc.json` → `cloudrun.name = "building-wiki"`（自动化端独立部署）
- `functions/agt-building-8gp5in9y2e59d69c/agent.yaml` + `scf_bootstrap`（Agent 为云函数）

## 2 · 技能定位（skill = 场景作业标准）

**条款**
skill = **一个场景的固化工作流**（作业标准），与 Agent **一一对应**
（设计约定，非平台强制——平台本身允许一个 Agent 挂多个 skill）。

**技能组成**
手册（流程 + 红线 + 契约）+ 脚本（确定性工具）+ `packs`（数据）。

**执行归属（本条要点）**
**技能本身不是执行者**；执行的发起者始终是 **Agent**。
技能只**提供给** Agent：规定它该怎么做（手册）、给它工具（脚本）、给它依据（packs）。
即：**技能规定 Agent，Agent 执行；技能自己不动作。**

**判据**
1. Agent 行为必须由 skill 手册规定，不得自创流程。
2. 技能不承载风格事实，风格全部下沉 `packs`。
3. **当前形态：单专家 + 单 Agent + 单 skill + 多风格知识包**（1 : 1 : 1）。
   「多」只发生在**数据层**（`packs/<style>/`），不发生在线路层（Agent / skill）。
   多专家**不在当前范围内**，不据此设计。

**代价（明记）**
一一对应 ⇒ 多专家要多套部署单元；换来的是「一个专家 = 一个可独立打包的单元」。

**依据**（实盘，2026-09-27 核实）
- `functions/agt-building-8gp5in9y2e59d69c/skills/` 下仅 `traditional-building` 一个（1:1 现状）
- `.../traditional-building/packs/` 下 `siheyuan` + `jiangnan` 两个（技能不承载风格事实）
- `SKILL.md` 的 frontmatter（`name`/`description`）+ 正文流程 = 作业标准
- `assemble.mjs` / `upload_instance.mjs` = 脚本，由 Agent 用 Bash 调用
- OAK `skills.enabled` 支持数组（平台允许 1:N，我们选 1:1）

## 3 · 专家定位（专家 = Agent 的人设）

**条款**
「专家」在本架构中**不是独立层、没有独立工件**；它 = **Agent 的人设**（`agent.yaml` 的 `system` 字段）。
因此：**1 个专家 = 1 个 Agent = 1 个人设 = 1 个 skill**（与总纲 1、2 的 1:1 一致）。

**边界**
技能 = 怎么做（`SKILL.md`）；人设 = 是谁 / 懂什么 / 守什么（`system`）。互补不重叠，同挂一个 Agent 名下。

**判据**
1. 不存在 expert 独立文件 / 目录。
2. 专家身份只写在 `system` 一处。
3. 人设只管「是谁 / 懂什么 / 守什么」，流程一律归 `SKILL.md`。

**依据**（实盘 + 官方，2026-09-27 核实）
- 官方 `/ai/agent/knowledgebase` 字段说明：`system` = 「人设 / 系统提示词」
- OAK `createAgent` 全 20 字段无 expert / persona
- 实盘 `functions/agt-building-8gp5in9y2e59d69c/` 下无 expert 工件

## 4 · 智能 / 自动化分界

**条款**
分界 = **实例图谱**（自包含 JSON），**不是进程 / 部署边界**。
智能侧 = ① 理解（LLM）+ 装配（确定性脚本）；自动化侧 = ④ 几何计算 + ⑤ 造型。

**衔接三要素**
1. 通道：`cos:instances/<uuid>.json`（云存储）
2. 契约：MCP 工具 `generate_building(instance_ref)`
3. 内容：图谱自包含（`data + appliedRules + appliedDict`）

**判据**
1. 自动化端不引用知识包（容器不 COPY packs）。
2. 自动化端只吃图谱快照。
3. 自动化端输出**体素 BOX 数据**，不输出「模型」——模型由前端渲染。

**附**
两侧各有一道硬闸（智能侧装配出口 / 自动化侧 ④⑤ 之前），共用同一事实源；**硬闸 ≠ 分界**。

**待核**
（已结清，2026-09-27）原记「`mcp_server.py` 实际暴露 4 个工具……后两个是否仍在使用待查」——
裁决：`compute_geometry` / `geometry_to_boxes` 是「前端两步直连」时代的遗留，已删除，
只留 `ping` + `generate_building`（见总纲 5）。

**依据**（实盘，2026-09-27 核实）
- `server/Dockerfile` 注释原话：「知识包不进容器。其唯一权威源在函数端 Skill 目录，服务端运行时(④⑤/硬闸)只引用实例图谱自带的 appliedRules/appliedDict 快照，绝不回读盘包。」
- `server/Dockerfile` 管线注释：「Agent（LLM 出骨架 → skill 装配实例图谱）→ MCP generate_building（内部 ④ compute_geometry → ⑤ geometry_to_boxes）→ 客户端渲染（前端独立部署，不在本容器内）」
- `server/Dockerfile` COPY 清单：`app.py / mcp_server.py / storage.py / engine / data`（**无 packs**）
- `server/mcp_server.py` 工具定义
- `server/mcp_server.py` 全文无 `packs` 引用（grep 无命中）→ 自动化端确不碰知识包

## 5 · MCP 职责（单入口）

**条款**
MCP（自动化端）**只做一件事**：吃实例图谱 → 出体素数据（④ 几何计算 + ⑤ 造型）。
对外**单入口** `generate_building(instance_ref)`（by-reference，④⑤ 一体化），
外加一个 `ping` 做冒烟。**不**把 ④ / ⑤ 各自单独暴露成工具。

**判据**
1. MCP 不碰知识包、不做智能判断（只做确定性计算）。
2. Agent 只需认识**一个**几何工具——不必知道 ④⑤ 的分步。
3. 「按引用读回实例图谱」是该入口的**内部步骤**，不是一次工具调用。
4. 出参与入参对称走引用：入参 `cos:<key>`，出参云存储预签名 URL（绕开 harness 对大输出的截断）。

**已执行**（2026-09-27）
删除 `compute_geometry` / `geometry_to_boxes` 两个遗留工具；同步清理 4 处陈旧引用：
`server/app.py`（工具清单注释）、`server/Dockerfile`（管线注释）、
`functions/.../agent.yaml`（工具命名示例）、`web/app.js`（`toolLabel()` 两行死映射）。

**依据**（实盘，2026-09-27 核实）
- `server/mcp_server.py` —— 仅两个 `@mcp.tool`：`ping` / `generate_building`；
  `compute_geometry` / `geometry_to_boxes` 仍 import，但只作 `generate_building_tool` 内部的**函数**调用
- `web/config.js` `MCP_URL` → `.../mcp/`（前后端都不再直连 ④⑤）
- `functions/.../agent.yaml` 注释 n°3：「工具在 Agent 侧命名为 `mcp__{serverName}__{toolName}`（即 `mcp__building-wiki__ping / __generate_building`）」
