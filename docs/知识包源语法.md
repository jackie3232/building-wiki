# building.wiki · 知识包源语法

> **用途**：定义知识包**源**（人写的 `.md` 词条）的书写语法，以及源 → 三件套片段的**编译规则**。
> **可执行实现**：`tools/kb/compile.py`。本文与实现冲突时，以实现为准，并回头修本文。
> **上位关系**：字段归口遵循《知识包三件套定义》§2 判据；本文只解决「**怎么把它写下来**」。
> **创建**：2026-09-28

---

## 0 · 一句话

> **一个对象一篇词条，一行一个字段；字段名决定归口，点路径决定层级。**
> 源是**权威**，`build/*.json` 是**缓存**（可随时重建，不入库）。

```
packs/<style>/src/<key>.md          源     —— 人写，入库
packs/<style>/build/<key>.json      产物   —— 机器读，可删可重建，.gitignore
```

**现状（2026-09-28，诚实声明）**：盘包（`dict.json` / `<style>.rules` / `<style>.type.json`）
仍是**运行期唯一输入**；`src/` 目前只覆盖 3 个词条（`chuihuamen` / `courtyard` / `zhengfang`），
`compile.py` 对它们执行的是「**源可 1:1 还原盘包**」的**校验**（还不是覆盖写盘包的生成器）。
其余词条与全部 `rules` / `type` 段仍无源路由（见 §4.3）。

**两条纪律**（在覆盖尚未铺满前必须守）：

1. **先改源、再改盘包**：某词条一旦有源，改它的知识就必须先改 `.md`、再跑 `compile.py --check` 确认零漂移；
   **禁止只改盘包不改源**（那会让源当场变成假权威）。
2. **写盘包必须保字节格式**：`<style>.rules` / `<style>.type.json` 的手工编辑须满足
   `json.dumps(obj, indent=2, ensure_ascii=False)` + 尾换行（往返逐字节精确）；
   `dict.json` **是例外**（手写紧凑数组）——**不可**用 `json.dumps` 整体重写。

## 1 · 文件与命名

| 项 | 规则 |
|---|---|
| 目录 | `functions/<fn>/skills/traditional-building/packs/<style>/src/` |
| 文件名 | `<key>.md`，`key` = 词条在 dict / type 里的 key（如 `chuihuamen.md`） |
| 粒度 | **一个对象一篇词条**。一篇词条 = 该对象在**三件套里的全部知识**（dict 段 + type 段 + norms 段 + form 段） |
| 编码 | UTF-8 |

**词条不是「一文件一 JSON 段」**：`courtyard.md` 写的是 `type` 段，`chuihuamen.md` 写的是 `dict` + `norms` + `form` 段。写哪几段，由源里出现哪些字段决定；**编译器不补齐、不凭空生成未写的段**。

## 2 · 标题行（必需）

```markdown
## 垂花门 (chuihuamen)
```

| 规则 | 说明 |
|---|---|
| 形式 | `## <中文名> (<key>)`，**半角括号**、`key` 限 `\w`（字母/数字/下划线） |
| 中文名 | 用于兜底生成 `dict.label`；也给人看 |
| key | 该词条在盘包里的 key，**必须与 dict / type 中的 key 一致** |
| 出现次数 | 每篇**恰好一条**；缺则 fail-fast 报「缺 '## 中文名 (key)' 标题行」 |

## 3 · 字段行（主体）

```markdown
是什么：分隔外院与内院的内门，装饰性
结构.center.ref：tingyuan
形体参数.gateSpan：3.0
```

| 规则 | 说明 |
|---|---|
| 形式 | `<字段><分隔符><值>`，一行一条 |
| 分隔符 | **全角 `：` 或半角 `:` 均可**，后允许空格 |
| 字段名 | 不得以空白或 `#` 开头；**字段名内不得含 `：` / `:`**（否则被当分隔符切走） |
| 值 | 单行、不去引号。**不支持多行值**；需长文本就一行写完（`desc` 常这样） |
| 忽略行 | 空行、以 `#` 开头（含 `##`）的注释行 |
| 缩进 | 忽略（但建议 `结构.*` 按层级缩进以便人读） |

---

## 4 · 字段路由表（一个字段 = 一件，谁都不许跨）

字段名 → 目标段。**写错字段名即报错，不会静默丢弃。**

### 4.1 精确字段（EXACT）

| 源字段 | 目标 | 值类型 | 归口理由 |
|---|---|---|---|
| `是什么` | `dict.desc` | 字符串 | 词的定义（三件套 §2「词**是什么**」） |
| `等级` | `dict.level` | 标量（dict key，如 `yideng`） | 固有属性 |
| `材质` | `dict.material` | 标量（dict key，如 `qingzhuan`） | 固有属性 |
| `颜色` | `dict.color` | 字符串（`#RRGGBB`） | 图示色（前端 role→色块） |
| `可变量` | `dict.modular` | **逗号列表** → 数组 | 固有属性（列表型） |
| `组成` | `dict.structs` | **逗号列表** → 数组 | 固有属性（列表型） |
| `形体原型` | `dict.form.kind` | 标量（原语名，见 §6） | 形体声明 |
| `形体方位` | `dict.form.at` | 标量（`east-end` / `west-end` / `center`） | 门道嵌在宿主房屋的哪一端 |
| `形体门楼` | `dict.form.tower` | **bool**（`true` / `false`） | 门道间是否带门楼 |
| `形体说明` | `rules.norms.desc` | 字符串 | 该形体的**文字描述**，不写数字 |

> 说明 1：`形体说明` 落在 `norms.desc` 而非 `dict`，因为它是「这栋房子**怎么算**」的口径说明，与同段的数值参数同源共处；词条自身的「是什么」在 `dict.desc`。二者不可互抄。
>
> 说明 2：`形体原型` / `形体方位` / `形体门楼` 三者同归 `dict.<key>.form` 一段——**分列三个字段而非一个 `形体.<路径>` 前缀**，是为了让「一个字段 = 一件」在字面上就成立（`形体.` 前缀会让 `kind/at/tower` 变成开放式路径，与 §4.3 的封闭路由精神相左）。原语若将来扩到第 4 个属性，再在 EXACT 加一行即可，不改语法。

### 4.2 前缀字段（PREFIX）

| 源字段形式 | 目标 | 值类型 |
|---|---|---|
| `结构.<路径>` | `type.<路径>` | 标量 |
| `形体参数.<路径>` | `rules.norms.<路径>` | 标量 |

**前缀字段必须带路径**：只写 `结构：xxx` 而不写 `结构.xxx：` → fail-fast 报「「结构」必须写成「结构.路径」」。

### 4.3 目前**没有**源路由的段（诚实声明）

| 段 | 现状 |
|---|---|
| `rules.paramRanges / orientation / position / usage / sequence / occupancy / wall` | **无源路由**，仍直接改 `siheyuan.rules` |
| `type.modularParams` / `type.wall` / `type.site` | 无源路由（`结构.modularParams.*` 技术上可写，但尚无词条用它） |

**词条覆盖面**：`空间角色` 类目共 18 个 key（`zhengfang` … `buqiang`），`构件` 7 个；
目前只有 `chuihuamen` / `zhengfang`（空间角色）+ `courtyard`（仅 type 段）3 篇有源。
其余词条虽**字段路由已可写**（§4.1 全覆盖），但尚未落源 —— 属迁移进度，不是结构缺口。

> 这是路线图中间态，不是设计。补源路由 = 在 `EXACT` / `PREFIX` 加一行，不改语法。

## 5 · 点路径语法

**嵌套用点，数组用下标。** 语法仅两段：`name` 与 `name[i]`，可任意串联。

```
结构.ring.sides.bei.wallRef     →  type.ring.sides.bei.wallRef
结构.peripheral[0].ref          →  type.peripheral[0].ref
结构.peripheral[2].attachToRef  →  type.peripheral[2].attachToRef
```

| 规则 | 说明 |
|---|---|
| 分层 | `.` 分隔，逐层 `setdefault`，**中间层不必预先声明** |
| 数组 | `name[i]`，下标从 **0** 起 |
| 稀疏下标 | 写 `peripheral[2]` 时，若 `[0]`/`[1]` 未写会先补**空对象**占位 —— 故数组**必须从 `[0]` 起按序写全** |
| 重复字段 | 同一路径写两次 → fail-fast 报「字段重复：<路径>」 |
| 非法段 | 段不是 `name` 或 `name[i]`（如 `a..b`、`a[]`） → fail-fast |
| 深度 | 当前最深用到 5 层（`结构.ring.sides.bei.wallRef`）；**超过三层仍可用**，但若某词条普遍超过 5 层，再议换 YAML —— 现在换属过度设计 |

**为什么不是 YAML**：嵌套实际只有两层（`sides.*` / `peripheral[i]`），点路径**零依赖、零缩进陷阱、与 `字段：值` 同构**，且歧义风险比缩进语言低。换语言没有收益。

## 6 · 值与取值规则

| 值形态 | 结果 | 例 |
|---|---|---|
| `^-?\d+$` | **int** | `5` → `5`；`-3` → `-3` |
| `^-?\d+\.\d+$` | **float** | `3.0` → `3.0` |
| `true` / `false` | **bool** | `true` → `True`（用于 `形体门楼`） |
| 其它 | **原样字符串**（不剥引号、不去尾空格以外的东西） | `room` → `"room"` |
| `可变量` / `组成` 的值 | 按**半角逗号**切分 → 数组，元素再按上表定标量 | `men, qiangti, wuoding` → `["men","qiangti","wuoding"]` |

注意：
- `3.` `1e3` `0x10` **不会**被转成数字（正则不匹配），会原样成字符串 —— 数值一律写成 `3` 或 `3.0`。
- `true` / `false` 是**保留字面量**，会转成布尔；想让 `desc` 里出现这两串英文，写成别的形式（如 `"true"` 会连引号一起保留，因为引号无特殊语义——但那也会被识别为字符串 `"true"` 含引号，故直接改写措辞最稳）。
- 引号无特殊语义，`desc：他说"好"` 会保留引号原样。

**形体原语（`形体原型` 的取值域）**：

| 原语 | 含义 |
|---|---|
| `box` | 单个长方块（位置 + 宽/高/深） |
| `repeat` | 沿轴重复（如游廊柱列） |
| `open` | 留空 / 开洞 |
| `room` | 复合原型 = 台基 + 屋顶 + 四壁（朝院一侧留门洞），由 `box` 组合而成 |
| ~~`slope`~~ | **坡屋顶当前没有**，需要时再补 |

## 7 · 报错规则（fail-fast，一律中止并给出行号）

| 触发 | 报错 |
|---|---|
| 缺标题行 | `缺 '## 中文名 (key)' 标题行` |
| 行不是「字段：值」 | `<文件> 第 N 行：不是「字段：值」格式 -> <原文>` |
| 未知字段 | `<文件> 第 N 行：未知字段「X」（合法：… / 结构.* / 形体参数.*）` |
| 前缀字段缺路径 | `<文件> 第 N 行：「X」必须写成「X.路径」` |
| 路径段非法 | `路径段非法：'a[]'（期望 name 或 name[i]）` |
| 同路径重复 | `字段重复：<路径>` |

设计意图：**源是权威，编译器不许猜。** 任何「没写明」都不许变成「静默用默认值」——否则源与产物两张皮，就退回到历史上 `houmen` 那种「代码硬编 vs 规则库打架」的坑。

## 8 · 编译与校验

```bash
python tools/kb/compile.py            # 编译 + 与现有盘包逐字段比对 + 写 build/
python tools/kb/compile.py --check    # 只比对，不写盘
python tools/kb/compile.py --style siheyuan
```

| 步骤 | 行为 |
|---|---|
| 读源 | `packs/<style>/src/*.md`，按文件名排序 |
| 解析 | §2~§6 规则 → `{dict:{}, type:{}, norms:{}}` |
| 比对 | 与**现有盘包**逐字段比：`dict` 取全类目查 key（**含 `form` / `color`**）；`type` 取 `type.<key>`；`norms` 取 `rules.norms.<key>`。逐字段打印 `[OK]` / `[DIFF]` |
| 结论 | 全 OK → 「零漂移（源可 1:1 还原现有三件套）」；任一 DIFF → 「有漂移，schema 需修」 |
| 写盘 | 非 `--check` 时写 `build/<key>.json` |

**零漂移是迁移纪律**：迁一个词条，源必须能 1:1 还原盘包里已有的每个字段。

> **反面教训（2026-09-28 实证）**：`form` 曾单独成一个桶、只当 `[NEW]` 打印、从不参与比对 ——
> 于是 `chuihuamen.md` 里写着 `形体原型：room`、盘包实际是 `gate-passage`，工具照样报「零漂移」。
> 修法：把 `form` 并回 `dict.<key>.form` 参与逐字段比。**教训：`[NEW]` 这种「不算漂移」的豁免，
> 就是给「两张皮」留的后门；凡能落到盘包位置的字段，一律进比对。** 现无可豁免项。

## 9 · 完整示例

```markdown
## 垂花门 (chuihuamen)

# 形体原型=gate-passage（门道间，非 room）：嵌在院界（卡子墙）正中，
# 按 形体方位=center 摆放；形体门楼=true 即带门楼（垂花门楼子）。
是什么：分隔外院与内院的内门，装饰性
等级：sideng
材质：mugou
颜色：#82A33A
组成：men, qiangti, wuoding
形体原型：gate-passage
形体方位：center
形体门楼：true
形体参数.gateSpan：3.0
形体参数.height：3.6
形体参数.depth：1.2
形体说明：垂花门面阔约一间(3.0m，比照宅门门道 gateSpan)；门楼比门道顶(3.3)略抬高至3.6；depth=门道进深(米)。
```

```json
{
  "dict":   {"label":"垂花门","desc":"分隔外院与内院的内门，装饰性",
             "level":"sideng","material":"mugou","color":"#82A33A",
             "structs":["men","qiangti","wuoding"],
             "form":{"kind":"gate-passage","at":"center","tower":true}},
  "type":   {},
  "norms":  {"gateSpan":3.0,"height":3.6,"depth":1.2,"desc":"垂花门面阔约一间…"}
}
```

只写 `结构.*` 的词条（`courtyard.md`）则产物 `dict` 段为空 —— **不产 `label`**，因为该 key 只活在 `type` 里。

## 11 · 渲染器（与源语法无关，但同属 `tools/`）

```bash
python tools/preview/render.py --instance tools/kb/baseline/jin3.instance.json --out tools/preview/out
```

把 ⑤ 体素画成 PNG（**离线、零浏览器依赖**）：`render-<名>-iso.png` 等轴测 + `render-<名>-plan.png` 俯视平面。
平面图按 **东=+x、北=−z** 定方位（上北下南），带指北针、比例尺、role 色块图例，并叠标 **院角色**
（外院/内院/厅房院/后罩院，取自 ④ `_layout`）。存在原因见其 docstring：本机 headless chrome 渲 WebGL
会超时且出全白图，静态图才是可复核的证据形态。
