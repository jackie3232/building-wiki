# building.wiki · 知识包三件套定义

> **用途**：定义知识包（pack）内三类内容 —— **dict / type / rules** —— 的边界与相互关系，作为所有图谱 / 引擎 / 校验实现的**上位判据**。
> **上位关系**：本文是《架构总纲》**第 8 条判据 2** 的展开细则。与总纲冲突时以总纲为准；若要改本文的实质约定，须先改总纲。
> **依据**：ISO 12006-3:2022 / ISO/IEC 11179 / ISO 23386:2020 / ISO 23387:2020 / buildingSMART bSDD / IDS / W3C OWL（出处见 §5）。
> **创建**：2026-09-28

---

## 0 · 一句话

> **本体（Ontology）= dict + type + rules；实例图谱 = 本体 + parameters。**
> **词在 dict 定义、结构在 type 组织、约束在 rules 声明。**

---

## 1 · 三者定义

### 1.1 dict —— 词汇层 / 唯一命名权威

**是什么**：知识包里「词」的总表。给每个建筑对象 / 构件 / 方位 / 材质 / 等级 / 开间 / 用途……一个**唯一名字**，以及它的定义与固有属性。
**性质**：**通用、非本地化、不含项目或产品专属内容**（bSDD 原文：general definitions, **not localised**；not supposed to contain project- or product-specific terms）。
**上位对标**：ISO 12006-3 的 Objects+Properties；bSDD 的 Dictionary（Class + Property）；ISO/IEC 11179 的 Object Class + Property；ISO 23386 所治理的对象。
**能装什么**：对象自身的一切 —— 名字、定义、别名，以及**该对象的固有属性**（含**列表型属性**，如「由哪些构件构成」「用哪些模数槽」——ISO 12006-3 明列 list values 属合法的属性数据类型）。

### 1.2 type —— 结构层

**是什么**：把 dict 里的词**组织成一座建筑的拓扑**。回答「院落如何沿中轴排布、每院的四至是什么、墙环如何由建筑后檐墙分段实现、门从属于哪道边界」。
**性质**：**只组织、只 `ref`** —— 不重声明角色名，不定义对象自身的属性。
**上位对标**：ISO 23387 的 **data template**（其 taxonomy「describes the relationships between different building elements」，且「based on the concepts and rules」of 字典）；W3C OWL 的 **TBox**；ISO 12006-3 的 Relationships / Collections。

### 1.3 rules —— 约束层

**是什么**：声明「**必须 / 禁止 / 值域 / 缺省 / 触发条件**」。回答「哪几进必须有什么、垂花门只能在哪、后门何时才设、面阔取值范围是多少」。
**性质**：**只约束** —— 不定义词、不组织结构。它是总纲 6 校验器（`validateInstanceGraph`）的知识源。
**上位对标**：buildingSMART **IDS**（定义 information requirements）；OWL 的**公理**（axioms）。
**注意（边界更正）**：IDS 原文明确**不含设计规则** ——「IDS **cannot** be used to define design requirements or so called 'rules'」，设计规则须交外部 rule checker。而设计规制恰是本项目 rules 的核心。故本项目 rules ≈ **IDS 的信息要求 + 设计规则检查器**，比 IDS 宽一档。

## 2 · 归口判据（一票否决）

对任何一条待入库的知识，按顺序问三问，先命中者定性：

| 问题 | 归口 |
|---|---|
| 它在说「某个词**是什么**」？（名字、定义、别名、该对象的固有属性） | **dict** |
| 它在说「一个词**挂到**另一个词上」？（组合、承载、从属、序列、四至拓扑） | **type** |
| 它在说「**必须 / 禁止 / 值域 / 缺省 / 触发**」？ | **rules** |

铁律：**同一事实只允许一处表达**（单一事实源）。两处表达 = 缺陷（如历史上 `houmen` 的规则库缺省与代码硬编两处打架）。

## 3 · 依赖关系：引用图，不是逐级依赖链

> 本节回应「三件套之间是不是**严格依赖**」。

**结论：不是严格的三段线性依赖，而是有向无环的「引用图」（DAG）。**

| 关系 | 性质 | 权威依据 |
|---|---|---|
| type → dict | **单向引用**（type 用到的词须命中 dict） | ISO 23387：data template「**based on** the concepts and rules of ISO 23386… **uses the properties defined in the data dictionaries**」 |
| rules → dict | **直连引用**（**不经过** type） | IDS：「**references** bSDD **using URI, instead of copying its content**」 |
| rules → type | 单向引用 | —— |
| dict → type / rules | **无**。dict 不需要下游，单独拿出来即一本合法词典 | ISO 12006-3：字典本身即是可独立实例化的 information model |

三个要点：

1. **单向、不对称**：下游（type / rules）需要上游（dict）才能成立；上游完全不知道下游存在。
   - dict 单独存在 = 合法（一本词典）；
   - type 脱离 dict → `ref` 悬空；
   - rules 脱离 dict → 无词可约束。
2. **非传递（跳级边）**：rules 直接引用 dict，**不经过** type。所以三者是一个 DAG（`dict ← type ← rules`，另加 `dict ← rules`），**不是一条链**。
3. **引用 ≠ 复制**：按 IDS 的做法，用**引用**（本项目的 `ref` / dict key）而非复制内容。

## 4 · 权威对位表

| 本项 | 权威对位 | 权威原文关键句 |
|---|---|---|
| **dict** | ISO 12006-3 Objects+Properties ／ bSDD Dictionary ／ ISO 23386 | 「database that contains **metadata**」；「general definitions, **not localised**」；「The set of **properties** associated with an object provide the **formal definition of the object**」 |
| **type** | ISO 23387 data template ／ OWL TBox ／ ISO 12006-3 Relationships | 「provides a **taxonomy** that describes the **relationships between different building elements**」；「based on the concepts and rules of ISO 23386」 |
| **rules** | IDS ／ OWL axioms | 「defining **information requirements**」；「**references** bSDD **using URI, instead of copying**」；「**cannot** be used to define design requirements or so called 'rules'」 |

**一句话收口**：词在 dict 定义、结构在 type 组织、约束在 rules 声明；**type 与 rules 各自引用 dict，无线性依赖。**

## 5 · 权威出处

- **ISO 12006-3:2022**《Building construction — Organization of information about construction works — Part 3: Framework for object-oriented information》 — iso.org/standard/74932.html
- **buildingSMART bSDD** — bsdd.buildingsmart.org；技术数据模型 technical.buildingsmart.org/services/bsdd/data-structure
- **ISO/IEC 11179**（Metadata Registry）：Data Element = Object Class + Property + Representation + Value Domain
- **ISO 23386:2020**：描述 / 撰写 / 维护**属性（properties）**的方法论（Governance）
- **ISO 23387:2020**：**data templates**（结构化属性集），based on 字典的概念与关系
- **buildingSMART IDS** — buildingsmart.org/what-is-information-delivery-specification-ids
- **W3C OWL 2**：TBox / ABox / RBox；ontology ≠ database schema（开放世界语义、公理即推理规则）

## 6 · 三件套与实例图谱的关系

```
本体（Ontology）  =  dict  +  type（class graph）  +  rules
实例图谱（ABox）  =  本体  +  parameters（几进 / 具体尺寸 / 哪些角色落地）
```

- 三件套以 `dict.json` / `*.type.json` / `*.rules` 三个 **JSON 文件**落盘与读写；**OWL 仅作概念对标**（本体建模思想同构于 OWL TBox/ABox），不作存储介质。
- 引擎只做**查表 + 校验**（按 key 查 dict、`type.ref` 命中 dict、套 rules），无需 DL 推理，故不引入 OWL/RDF 解析器与推理机（与总纲 7 判据 1「引擎零风格硬编」一致）。
- **零坐标**：图谱只记语义与拓扑，绝对坐标由几何层（④）按模数与拓扑算出。
